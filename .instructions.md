# Development Quality Standards

This project requires strict code quality checks before major changes are committed. Follow this workflow for all substantial changes.

## Pre-Commit Quality Assurance Workflow

After making significant changes to components, styles, or logic, run the complete quality check sequence:

### Step 1: Lint Code
```bash
pnpm lint
```
This validates code style, best practices, and catches common mistakes using ESLint.

**When to run**: After every feature implementation, before pushing to version control.
**Expected**: No linting errors or warnings.

### Step 2: Type Check
```bash
pnpm typecheck
# OR if typecheck script isn't defined:
tsc --noEmit
```
This verifies type safety and catches TypeScript errors without building.

**When to run**: Before committing changes that touch TypeScript files.
**Expected**: All types resolve correctly, no `any` types unless explicitly allowed.

### Step 3: Build for Production
```bash
pnpm build
```
This creates an optimized production build and validates all code paths work correctly.

**When to run**: Before pushing feature branches or before final commit.
**Expected**: Build completes successfully with no errors (warnings are acceptable).

## Complete Quality Check (Recommended)

Run all checks together:
```bash
pnpm lint && tsc --noEmit && pnpm build
```

This ensures:
- ✅ Code follows linting standards
- ✅ All TypeScript types are valid
- ✅ Build succeeds with no runtime errors

## What Constitutes "Major Changes"

Run the full QA workflow when:
- Creating new components or modifying existing ones
- Changing TypeScript types or interfaces
- Updating styles or Tailwind configuration
- Modifying API routes or server actions
- Changing layout or page structure
- Upgrading dependencies

## Development Workflow

### During Development
```bash
pnpm dev
```
Start the development server. The dev server includes fast refresh and immediate feedback for most changes.

### Before Committing
```bash
pnpm lint && tsc --noEmit && pnpm build
```

### After Merging
Verify production build still works on the main branch.

## Troubleshooting Common Issues

### ESLint Errors
- Run `pnpm lint` to see all violations
- Most can be auto-fixed: `pnpm lint -- --fix`
- Review eslint.config.mjs for rule customizations

### TypeScript Errors
- Run `tsc --noEmit` to get detailed error messages
- Check tsconfig.json for type-checking configuration
- Use `@ts-expect-error` only when absolutely necessary with a comment

### Build Failures
- Clear `.next` cache: `rm -rf .next`
- Check that all components are properly exported
- Ensure Server/Client Component boundaries are correct
- Verify all imports resolve correctly

## IDE Integration

### VS Code Setup
1. Install ESLint and TypeScript extensions
2. Enable "Format on Save" for auto-fixing on save
3. Enable "Auto-save" for real-time feedback

Add to `.vscode/settings.json`:
```json
{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "eslint.validate": ["javascript", "javascriptreact", "typescript", "typescriptreact"],
  "eslint.run": "onSave",
  "[typescript]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.formatOnSave": true
  }
}
```

## Performance Notes

- Lint check: ~1-2 seconds
- Type check: ~2-5 seconds
- Build check: ~10-30 seconds depending on changes

Cache the results locally to speed up repeated checks in CI environments.

## Required Node Version

Ensure you're using Node 18+ and pnpm 8+:
```bash
node --version  # Should be v18.0.0 or higher
pnpm --version  # Should be 8.0.0 or higher
```
